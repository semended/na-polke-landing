# На полке

Каталог и заказы на самовывоз для одного магазина. Покупатель выбирает товары и оставляет заявку. Сотрудник видит её состав и контакты, согласует наличие и обновляет витрину.

## Запуск клиента

Из корня репозитория с Node.js 22.12+ и npm выполните:

```sh
cd mvp
npm ci
npm run dev
```

Откройте локальный адрес из терминала. Для проверки кода в папке `mvp` выполните `npm test` и `npm run build`. Первая команда запускает тесты предметной логики, Redux и React-компонентов. Вторая проверяет TypeScript и собирает сайт в `mvp/dist`. Команда `npm run preview` запускает локальный просмотр сборки.

Для браузерных тестов оставьте `npm run dev` запущенным. Во втором терминале из папки `mvp` выполните:

```sh
npx playwright install chromium
npm run test:e2e
```

Лендинг открывается отдельно из корневого `index.html`. Для него достаточно браузера. [Описание второго этапа](LANDING.md).

## Что показать на защите

1. **Гость оформляет самовывоз.** В каталоге найдите Haribo Phantasia. Добавьте две упаковки по 229 ₽ и откройте корзину. Итог — 458 ₽. При отправке пустой формы появятся подсказки. Введите вымышленные контакты, отправьте заказ и запомните его номер.
2. **Сотрудник разбирает заявку и меняет товар.** В меню «Профиль» выберите «Войти как сотрудник». Откройте заявку с этим номером и проверьте контакты, состав и сумму. Вернитесь в кабинет, измените цену Haribo или снимите отметку «В наличии». Откройте карточку в каталоге и сравните её со старым заказом. В заказе останутся исходные 229 ₽ за упаковку. Архивирование скрывает карточку с витрины.
3. **Покупатель смотрит свою историю.** Через «Профиль» войдите как Анна и оформите ещё один заказ. Откройте «Мои заказы», затем смените профиль на Ивана. Каждый видит только свои заказы, сделанные после входа. Гостевая заявка доступна сотруднику и не попадает в историю покупателя.

Сценарии проходят в профиле одного браузера. Выбор роли имитирует вход. Используйте вымышленные контакты. Для изолированного показа удобно открыть приложение в новом приватном окне.

## Как устроен клиент

| Где смотреть | Что объяснить |
| --- | --- |
| [Маршруты и оболочка](mvp/src/App.tsx) | Главная, каталог, товар, корзина, оформление, история, детали заказа, демо-вход и кабинет сотрудника. HashRouter позволяет обновить любую страницу на GitHub Pages. |
| [Страницы](mvp/src/pages/) и [компоненты](mvp/src/components/) | Карточки товаров, фотографии, поля и итог заказа используются в разных экранах. Страницы передают действия в Redux. |
| [Redux Toolkit](mvp/src/store.ts) | Слайсы изменяют состояние, селекторы определяют видимые товары и заказы. Загрузка каталога и отправка заказа проходят через `createAsyncThunk`. |
| [Типы и расчёты](mvp/src/domain.ts) | Фильтрация, нормализация телефона, проверка контактов, количество и сумма. Заказ хранит снимок товарных позиций. |
| [Хранилище](mvp/src/storage.ts) | Каталог и заказы сохраняются в браузере. Корзина, черновик и выбранный профиль относятся к сеансу вкладки. |
| [Тесты](mvp/tests/) | Примеры входных данных, ожидаемые результаты и сквозные действия пользователя. |

**Состояния каталога.** Откройте [имитацию ошибки](https://semended.github.io/na-polke-landing/mvp/#/catalog?demo=error) или [пустой каталог](https://semended.github.io/na-polke-landing/mvp/#/catalog?demo=empty). Кнопка «Повторить загрузку» вернёт товары. Пока каталог загружается, отображается индикатор. Для проверки пустого результата поиска введите название отсутствующего товара.

**Проверка в двух вкладках.** Оставьте оформление открытым у покупателя. В другой вкладке войдите как сотрудник и измените цену товара из корзины. Покупатель увидит старую и новую цену и сможет подтвердить обновлённую сумму. Если два сотрудника открыли один товар, сохранение устаревшей формы предложит перечитать карточку. Для редактирования нужен современный браузер с Web Locks на HTTPS или localhost.

**Граница третьего этапа.** Весь MVP работает без сервера. Данные доступны в браузере, где проходила демонстрация. Пароли, проверка прав на сервере, общая база заказов и интеграция через HTTP предусмотрены четвёртым этапом. План контрактов и сущностей приведён в техническом приложении.
