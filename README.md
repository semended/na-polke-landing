# На полке

Каталог и заказы на самовывоз для одного магазина. Покупатель выбирает товары и оставляет заявку. Сотрудник видит её состав и контакты, согласует наличие и обновляет витрину.

## Запуск клиента и проверок

Для разработки нужен Node.js 22.13+ (в CI — 24) и npm. Все команды выполняются в каталоге `mvp`.

```sh
npm ci
npm run dev
```

| Команда | Что делает |
| --- | --- |
| `npm run lint` и `npm run format:check` | Проверяют правила ESLint и формат Prettier. |
| `npm test` | Запускает Vitest для логики, Redux и компонентов. |
| `npm run storybook` | Открывает каталог компонентов. |
| `npm run test:stories` | Проверяет рендер и действия в сторис через Chromium. |
| `npm run build:pages` | Проверяет типы и собирает лендинг, MVP и Storybook в `.pages/na-polke-landing`. |
| `npm run test:demo` | Открывает собранный сайт и проходит сценарий защиты в Chromium и WebKit. |
| `npm run test:visual` | Сравнивает 14 скриншотов сайта с эталонами. |

Перед браузерными проверками выполните `npx playwright install chromium webkit`.
Для скриншотов используйте тот же образ Linux ARM64, что и в [GitHub Actions](.github/workflows/pages.yml).
Порядок обновления эталонов описан в [QA.md](QA.md#скриншоты-этапа-3).

## Что показать на защите

[Главная страница](https://semended.github.io/na-polke-landing/) сразу открывает каталог. [Storybook](https://semended.github.io/na-polke-landing/storybook/) открывается по отдельной ссылке.

1. **Гость оформляет самовывоз.** В каталоге найдите Haribo Phantasia. Добавьте две упаковки по 229 ₽ и откройте корзину. Итог — 458 ₽. При отправке пустой формы появятся подсказки. Введите вымышленные контакты, отправьте заказ и запомните его номер.
2. **Сотрудник разбирает заявку и меняет товар.** Внизу витрины нажмите «Вход для сотрудника» и выберите «Войти как сотрудник». Откройте заявку с этим номером и проверьте контакты, состав и сумму. Вернитесь в кабинет, измените цену Haribo или снимите отметку «В наличии». Откройте карточку в каталоге и сравните её со старым заказом. В заказе останутся исходные 229 ₽ за упаковку. Архивирование скрывает карточку с витрины.
3. **Покупатель смотрит свою историю.** Через «Профиль» войдите как Анна и оформите ещё один заказ. Откройте «Мои заказы», затем смените профиль на Ивана. Каждый видит только свои заказы, сделанные после входа. Гостевая заявка доступна сотруднику и не попадает в историю покупателя.

Сценарии проходят в профиле одного браузера. Выбор роли имитирует вход. Используйте вымышленные контакты. Для изолированного показа удобно открыть приложение в новом приватном окне.

## Как устроен клиент

| Где смотреть | Что объяснить |
| --- | --- |
| [Маршруты](mvp/src/ShopRoutes.tsx) и [оболочка](mvp/src/App.tsx) | Главная, каталог, товар, корзина, оформление, история, детали заказа, демо-вход и кабинет сотрудника. HashRouter позволяет обновить любую страницу на GitHub Pages. |
| [Страницы](mvp/src/pages/) и [компоненты](mvp/src/components/) | Карточки товаров, фотографии, поля и итог заказа используются в разных экранах. Страницы передают действия в Redux. |
| [Redux Toolkit](mvp/src/store.ts) | Слайсы изменяют состояние, селекторы определяют видимые товары и заказы. Загрузка каталога и отправка заказа проходят через `createAsyncThunk`. |
| [Типы и расчёты](mvp/src/domain.ts) | Фильтрация, нормализация телефона, проверка контактов, количество и сумма. Заказ хранит снимок товарных позиций. |
| [Хранилище](mvp/src/storage.ts) | Каталог и заказы сохраняются в браузере. Корзина, черновик и выбранный профиль относятся к сеансу вкладки. |
| [Браузерные тесты](mvp/tests/) | Покупка с главной страницы, работа сотрудника и скриншоты. Тесты функций и компонентов находятся рядом с исходниками в `src`. |

### Соглашения по коду

- Файлы React-компонентов именуются по экспортируемому компоненту. Страница связывает маршрут и Redux, небольшие компоненты получают данные и обработчики через props.
- Сумма корзины и другие производные значения вычисляются из исходного состояния. Расчёты и проверка контактов собраны в `domain.ts` рядом с `domain.test.ts`.
- Тесты и истории именуются `Имя.test.ts(x)` и `Имя.stories.tsx`. Storybook показывает состояние компонента на учебных данных. Playwright проверяет собранный сайт через обычные ссылки и кнопки.
- В качестве ориентира использованы [структура модулей Medusa Storefront](https://github.com/medusajs/dtc-starter/tree/main/apps/storefront/src/modules) и [руководство Thinking in React](https://react.dev/learn/thinking-in-react). Источники и лицензии фото перечислены в [SOURCES.md](SOURCES.md#фотографии-в-приложении-этапа-3).

**Состояния каталога.** Откройте [имитацию ошибки](https://semended.github.io/na-polke-landing/mvp/#/catalog?demo=error) или [пустой каталог](https://semended.github.io/na-polke-landing/mvp/#/catalog?demo=empty). Кнопка «Повторить загрузку» вернёт товары. Пока каталог загружается, отображается индикатор. Для проверки пустого результата поиска введите название отсутствующего товара.

**Проверка в двух вкладках.** Оставьте оформление открытым у покупателя. В другой вкладке войдите как сотрудник и измените цену товара из корзины. Покупатель увидит старую и новую цену и сможет подтвердить обновлённую сумму. Если два сотрудника открыли один товар, сохранение устаревшей формы предложит перечитать карточку. Для редактирования нужен современный браузер с Web Locks на HTTPS или localhost.

**Граница третьего этапа.** Весь MVP работает без сервера. Данные доступны в браузере, где проходила демонстрация. Пароли, проверка прав на сервере, общая база заказов и интеграция через HTTP предусмотрены четвёртым этапом. План контрактов и сущностей приведён в техническом приложении.
